# Zerium G Shield — blocking scope

## How it works

The shield is a built-in WebExtension loaded from the APK assets (`resource://android/assets/extension/`) through `WebExtensionController.ensureBuiltIn`. GeckoView gives extensions the full `webRequest` API with blocking — this is the difference engine-level blocking makes; the WebView edition of Zerium can only approximate it app-side.

1. **Network layer** (`background.js`): `browser.webRequest.onBeforeRequest` cancels requests whose host matches the bundled hosts list (hosts-file semantics: `example.com` covers `a.example.com`) or contains a curated URL pattern (84 rules: ad exchanges, analytics pixels, header bidding, popup networks — the same conservative pattern set as the WebView edition).
2. **Cosmetic layer** (`content/cosmetic.css`): 649 element-hiding selectors applied at `document_start` on every page — empty ad boxes never paint, including locally-inserted ones.
3. **Live control**: the app talks to the extension over GeckoView native messaging (`browser.runtime.connectNative`): `{type:"config", enabled, allowlist}` flows down; `{type:"count", blocked}` deltas flow up. Toggling blocking off, or allowing a site, takes effect immediately without reload.

## Rules data

`blocklist/rules.json` is generated by `scripts/gen_gecko_rules.py` in the Zerium Browser repository from that project's sources:

- **79,963 hosts** — StevenBlack unified hosts (adware + malware + fakenews + gambling + tracking), MIT licensed, bundled at build time.
- **84 URL patterns** — the curated substring set from the Zerium Browser `AdBlocker` (deliberately conservative to avoid breaking page function).

## Honest scope

- Hosts-file semantics plus substring patterns are not a full filter-list DSL: no `$domain=` qualifiers, no exception rules, no resource types. Deep filter syntax (uBlock Origin class) needs the extension platform work on the roadmap.
- The allowlist compares the exact request host and its registrable parents; a site entry does not unblock its embedded third parties (that is a feature here, not a bug).
- The YouTube-specific suppression layer from the WebView edition is not ported. Network blocking + ETP apply to YouTube; a dedicated Gecko-side scriptlet is roadmap work.
- Blocking counters are best-effort aggregates; the shield flushes counts at most every 5 seconds.
