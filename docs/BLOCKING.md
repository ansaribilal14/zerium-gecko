# Zerium G Shield — blocking scope

## How it works

The shield is a built-in WebExtension loaded from the APK assets (`resource://android/assets/extension/`) through `WebExtensionController.ensureBuiltIn`. GeckoView gives extensions the full `webRequest` API with blocking — this is the difference engine-level blocking makes; the WebView edition of Zerium can only approximate it app-side.

1. **Network layer** (`background.js`): `browser.webRequest.onBeforeRequest` evaluates every request against the compiled rule set (below) and cancels matches. Supported options: resource types (script, image, stylesheet, xmlhttprequest, subdocument, object, media, font, websocket, ping, other + `3p/1p/xhr/frame/css` aliases), `third-party`/`first-party`, `important`, `domain=` with `~` negation. `$important` rules beat `@@` exceptions, matching uBlock Origin semantics.
2. **YouTube InnerTube pruning** (`background.js`): responses from the player API endpoints (`player`, `next`, `get_watch`, `ssap`, `get_midroll_info`, …) are streamed through `browser.webRequest.filterResponseData` and pruned of ad structures (`adPlacements`, `adSlots`, `playerAds`, `adBreaks`, renderer-level ad keys) **inside the engine, before the page receives them** — the same AD_KEYS/deepPrune logic as the WebView edition's page-level script, now applied at the network layer where the page can never race it.
3. **Page-level YouTube layer** (`content/yt-inject.js` → `page/yt-block.js`): the WebView edition's proven v1.4.0 script runs in the page context at `document_start` (setter trap for `ytInitialPlayerResponse`, order-independent XHR response getters, fetch clone hook, UI sweep, confirmed-ad watchdog). It is the exact file validated by the 21-case black-box suite in the Zerium Browser repo.
4. **Cosmetic layer** (`content/cosmetic.css`): 4,000 element-hiding selectors applied at `document_start` on every page — empty ad boxes never paint, including locally-inserted ones.
5. **Live control**: the app talks to the extension over GeckoView native messaging (`browser.runtime.connectNative`): `{type:"config", enabled, allowlist}` flows down; `{type:"count", blocked}` deltas flow up. Toggling blocking off, or allowing a site, takes effect immediately without reload.

## Rules data

`blocklist/rules.json` (v2) and `content/cosmetic.css` are generated by `scripts/gen_gecko_rules.py` (also run weekly by CI in `update-rules.yml`):

- **79,963 hosts** — StevenBlack unified hosts (adware + malware + fakenews + gambling + tracking), MIT licensed.
- **91,450 domains** — `||host^` network filters compiled from EasyList + EasyPrivacy (CC-BY-SA-3.0).
- **11,577 path filters** — `||host/path…` rules with the supported option subset.
- **1,131 exceptions** — `@@` rules, including `$document` page-level exceptions.
- **84 URL patterns** — the curated substring set from the Zerium Browser `AdBlocker` (deliberately conservative to avoid breaking page function).
- **4,000 cosmetic selectors** — sanitized generic-hide subset of EasyList/EasyPrivacy.

## Honest scope

- The network engine is a **subset of the Adblock syntax, not the full DSL**: regex filters, `|http` anchors, wildcard hosts, `$popup`, `$csp`, `$redirect`, `$replace`, `$removeparam`, `$webrtc`, `$generichide`/`$specifichide`/`$elemhide` cosmetic-scope exceptions and domain-scoped element hiding are **not implemented** — the generator drops rules carrying them rather than approximating. Procedural selectors (`:has-text`, `:-abp-…`) are likewise out of scope.
- The allowlist compares the exact request host and its registrable parents; a site entry does not unblock its embedded third parties (that is a feature here, not a bug).
- The YouTube suppression layer ships, but with the same honest boundary as the WebView edition: SSAP (server-side ad stitching) mid-rolls are part of the media stream itself and cannot be removed client-side; the confirmed-ad watchdog fast-forwards through them instead.
- Blocking counters are best-effort aggregates; the shield flushes counts at most every 5 seconds.
- Reader-view extraction parses the DOM snapshot at `document_idle` (same as Firefox's reader and the WebView edition); paywalled or JS-gated content yields what is actually in the DOM.
